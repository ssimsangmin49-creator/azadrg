Field Data Collection, Anomaly Detection & Validation Methodology

From field operation to traceable evidence — an open framework for research and community trials.

Non-commercialProposed methodologyReproducibilityData quality
Scope and status. This document describes a proposed data architecture and validation methodology for future AFC/SSOF field trials. It does not claim that a live multi-site platform, automated validation system, or independently certified environmental outcome already exists.

1. End-to-End Data Architecture

→

→

Each participating unit generates time-stamped operating records. An IoT edge module collects available sensor readings and transfers them to a mobile device, which can relay records to a web server when connectivity is available. The server supports long-term storage, comparison, review and controlled sharing. Offline buffering and retransmission should be considered during development.

2. Proposed Data Items

  • Unit and site identifiers; configuration and sensor metadata
  • Temperature by measurement point or stage
  • Operating time, start/stop events and status
  • Feedstock type and treatment mass, where independently measured
  • Airflow and pressure, where sensors are installed
  • Auxiliary energy or fuel use, where measured
  • Emissions indicators, only where appropriate instruments or tests are available
  • Maintenance, calibration, alarms and operator observations

All values should carry units, timestamps, measurement methods and quality flags.

3. Cumulative Reference Profiles

As field data accumulates, reviewed records can establish reference profiles for comparable units and operating conditions.

  • Compare like with like: model, configuration, feedstock, operating phase and sensor placement
  • Track variability, operating ranges and recurring patterns
  • Preserve raw records separately from cleaned and validated datasets
  • Record the version and provenance of each reference profile

Initial reference profiles may be limited and should be revised as more evidence becomes available.

4. Anomaly Detection & Review

Incoming RecordRaw, time-stamped
→
Quality ChecksMissing, duplicate, range, sensor drift
→
Profile ComparisonTrends and deviations
→
Flag for ReviewUnusual ≠ invalid

Potential anomalies may arise from a sensor or communication fault, a genuine change in operating conditions, an unusual but valid operating event, or an unresolved cause. The detection algorithm should flag and classify such records rather than silently delete or overwrite them.

Early implementation can begin with transparent rules and statistical thresholds. More advanced algorithms may be evaluated only after sufficient labeled field data becomes available.

5. Verification, Traceability & Data Status

  1. Cross-check: compare sensor streams with operating logs, calibration records, feedstock measurements and available independent observations.
  2. Review: assign a cause when evidence permits; otherwise keep the record unresolved.
  3. Classify: verified normal, verified operating anomaly, confirmed measurement error, or pending review.
  4. Preserve: retain the original record, corrected or derived version, reviewer, method, timestamp and reason for any change.
  5. Share: make reviewed datasets available to authorized stakeholders according to agreed access and data-rights arrangements.

Automated anomaly detection is not itself independent environmental verification or regulatory certification.

6. Value & Role of Reviewed Data

Technical Value

Reproducible operating profiles, performance comparison, maintenance diagnostics, algorithm improvement and future Digital Twin research.

Public Value

Traceable operating records for host communities, public authorities, program evaluation and evidence-informed support decisions.

Research Value

Shared data definitions, documented uncertainty and field datasets for universities and technical partners to develop and test methods.

Potential Economic Value

Verified treatment records may support future environmental-finance assessments, including Plastic Credit or ReFi research, subject to applicable methodologies and independent verification.

A verified operating record is not automatically a verified emissions reduction, carbon credit, plastic credit or financial asset. Each claim requires its own evidence and applicable assessment standard.

7. University & Research Collaboration

AZADrg can contribute AFC/SSOF field experience, system definitions and available field evidence. Research partners can help design, implement and test the data pipeline and validation methods.

  • IoT edge firmware, mobile synchronization and secure server ingestion
  • Open data schema, quality-control rules and versioned datasets
  • Anomaly detection, classification and explainable review workflows
  • Statistical validation, uncertainty analysis and Digital Twin feasibility
  • Reproducible documentation and field testing with local partners

Research principle: publish methods, assumptions, limits and results clearly, while defining field-data access and usage rights with the host community or country and participating organizations.
